# Veil — Roadmap

План развития панели по итогам сравнения с популярными VPN-панелями
(3x-ui / Marzban / X-UI / Aurora / Firefly): что у них есть «из коробки»,
чего не хватало Veil, и в каком порядке это внедряется.

## Фаза 1 — Зрелость сервиса ✅ (v2.5.0)

То, чем пользователи пользуются каждый день и что есть у всех конкурентов.

| # | Фича | Статус |
|---|------|--------|
| P1 | `subscription-userinfo` в /sub (остаток трафика/срок в клиентских приложениях) + ссылка на standalone sing-box конфиг | ✅ v2.5.0 |
| P2 | Циклы сброса трафика (день/неделя/месяц/lifetime) с дельта-накоплением из Xray-счётчиков + Telegram-алерты (80 % лимита, остаток дней, автоблокировка) | ✅ v2.5.0 |

## Фаза 2 — Мультиузловость и масштабируемость

Для продавцов, у которых несколько серверов и десятки клиентов.

- **W1. Agent-режим → полноценная mesh**: удалённые узлы как юниты
  (`nodes.json` уже есть задел) — создание клиентов на всех узлах одной
  кнопкой, агрегированный трафик/статус,healthcheck узлов с авто-алертом.
- **W2. Маршрутизация подписки**: один `/sub`-токен, который отдаёт разные
  конфиги в зависимости от региона клиента (GeoIP по source) — клиент
  всегда получает ближайший узел.
- **W3. Бэкапы и восстановление из UI**: шифрованный снапшот
  (state/config/certs/sessions) на GitHub-приватный репозиторий или S3,
  расписание, восстановление «в одну кнопку» на голой машине.
- **W4. Права и роли**: оператор-аккаунт без доступа к настройкам
  сервера; аудит уже есть (`/api/audit`) — добавить фильтры и экспорт CSV.
- **W5. Вебхуки**: события (клиент создан/заблокирован/истёк, узел упал)
  → POST на URL — интеграция с биллингами (WISECP, HostBill).

## Фаза 3 — Продуктовость

- **E1. Onboarding-мастер**: домен → сертификат (ACME есть) → первый
  inbound → первый клиент → QR — один пошаговый визард при первом входе.
- **E2. Красивые страницы подписки**: брендирование (логотип/цвета уже
  принимаются), подписочная страница с экспирацией и пополнением.
- **E3. Статистика в UI**: графики трафика по дням (накопленные
  `_traffic_tick`-данные писать в кольцевой журнал), топ-клиенты,
  прогноз истечения.
- **E4. Мобильный APK-клиент White-label**: сборка Happ/v2rayTun-профиля
  с подшитым URL подписки через build-сервис — опционально.
- **E5. Мультиязычность UI**: ru/en переключатель (сейчас только ru).

## Принципы

- Stdlib-only, один файл `panel.py`, никаких pip-зависимостей — сохраняется
  переносимость на голую Ubuntu/Debian одним `install.sh`.
- Никаких внешних вызовов кроме явно настроенных (GitHub-релизы для
  зеркал правил — единственный allow-list'ed исходящий URL вне API).
- Все опасные действия (бан, откат, перезапуск Xray) — идемпотентны и
  оставляют след в `audit.json`.
