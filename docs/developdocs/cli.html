Использование CLI

У панели нет команды-обёртки и --help: она умеет запускаться как служба и принимать ровно два флага. Всё остальное в работе разработчика делают install.sh и батарея приборов.

panel.py

Обычный запуск — без аргументов: панель читает config.json, берёт panel_port (заводское 8443) и встает на него. Перед любым записыванием на диск ставится замок порта:

port = CFG_CACHE.get("panel_port", 8443)
bind = (CFG_CACHE.get("panel_bind") or "0.0.0.0").strip()
_taken = _panel_port_taken(bind, port)
if _taken:
    print("VEILERR: запуск отменён: " + _taken, file=sys.stderr, flush=True)
    sys.exit(1)

Второй экземпляр панели рукой переписал бы живой конфиг ядра под носом у первого, поэтому отказ — не вежливость, а защита. Текст VEILERR: запуск отменён и есть причина, прочитанная вслух.

Флаг --dns01-hook

python3 panel.py --dns01-hook auth      # или cleanup

Это крюк certbot (--manual-auth-hook / --manual-cleanup-hook) для выпуска сертификата по DNS-01. Действие читается вторым словом, остальное берётся из окружения certbot: обязательны CERTBOT_DOMAIN и CERTBOT_VALIDATION. Работает только с Cloudflare. Код возврата — 0 успех, 1 отказ, причина уходит в stderr с префиксом dns01-hook:.

Флаг --migrate-apply

sudo python3 /opt/vpnpanel/panel.py --migrate-apply /tmp/veil-mv.tar.gz

Ножка «переезда»: разбирает архив, составленный на старой машине, и раскладывает его сюда — конфиг, состояние, юниты. Требует root; ошибки печатаются с префиксом VEILERR: переезд(apply):. Приватные файлы (_MV_PRIVATE) в такой архив не попадают по определению.

Других флагов нет. Ни argparse, ни подкоманд, ни --help: список выше — это весь if __name__ == "__main__". Всё остальное делается через HTTP-API мордой или curl-запросом к /api/*.

install.sh

bash install.sh                # интерактивное меню управления
bash install.sh --step N       # выполнить только шаг N (0–6)
bash install.sh --dry-run      # показать команды, не выполнять
bash install.sh --lang ru|en   # язык сообщений
bash install.sh --help         # это сообщение

Любой другой аргумент — отказ с текстом «неизвестный аргумент». Без аргументов меню предлагает пять пунктов: установить, переустановить с сохранением данных, переустановить с удалением данных, удалить панель полностью, показать адрес панели.

Установщик качает релиз …/releases/latest/download/veil.tar.gz и сверяет его по veil.tar.gz.sha256 до распаковки. Nginx и sing-box установщик не ставит: их подключает сама панель, когда включает SNI-мюкс или sing-box-выдачу.

vpnpanel.service

systemctl restart vpnpanel             # перезапуск после переноса байтов
systemctl is-active vpnpanel
journalctl -u vpnpanel -e              # «Veil 2.17.48 слушает …»
systemctl cat vpnpanel

Юнит лежит в /etc/systemd/system/vpnpanel.service, ExecStart — /usr/bin/python3 /opt/vpnpanel/panel.py, рядом Restart=always, RestartSec=2, LimitNOFILE=65535. Тот же текст пишет и --migrate-apply, поэтому юнит на переехавшей машине не отличается.

Порядок «сначала на бой». Панель перезапускают осознанно и сверяют байты до и после: контрольная сумма sha256 первых двенадцати символов panel.py и index.html до перезапуска и строка версии в журнале после. Журнал обязан сказать ту версию, которую занесли.

battery.sh — батарея приборов

Полигон лежит в backups/audit-2.16.1/gp/: battery.sh и 209 приборов (73 cc*, 104 f*). Каждый прибор — самостоятельный *_test.py с нулевым кодом возврата, когда всё зелено.

cd backups/audit-2.16.1/gp

bash battery.sh 100              # тег battery100-<метка времени>
POOL=small bash battery.sh 100s  # деликатный пул (~16 мин против ~113)
LIVE=1 bash battery.sh 100l      # добавить живые прогоны — решение владельца
STREAMS=3 bash battery.sh 100    # число потоков пула, по умолчанию 2
STREAM=2 bash battery.sh 100     # один поток из NSTREAM
bash battery.sh --list           # состав пула «файл|флаги», без прогона

Кто попадает в пул

  • Состав определяется не именем файла: берутся все *_test.py каталога.
  • offline_excluded.txt вычёркивает приборы: голое имя — пропустить, имя --флаг — прогнать с этим флагом (совпадение полное, не по подстроке).
  • Приборы с токеном live идут только при LIVE=1.
  • POOL=small оставляет ровно то, что перечислено в small_pool.txt целым именем (формат строки — имя секунды). Список растёт вместе с мерами: в этом дереве в нём 122 прибора на сумму хода 1437 с, а шапка battery.sh говорит про ~16 мин в два потока против ~113 мин полного пула. Сам список закрепляет прибор cc57.

Отказ до старта

Батарея не начинает прогон и выходит с rc=3, назвав число, если:

  • POOL не full и не small;
  • STREAMS/STREAM не число или вне диапазона;
  • POOL=small, а small_pool.txt пуст или не читается;
  • свободного диска меньше 300 МиБ, MemAvailable меньше 700 МиБ, /tmp меньше 200 МиБ;
  • нет потолка cgroup v2.

Как судится прогон

Потолок памяти — CEIL = MemAvailable * 3 / 4; он пишется в /sys/fs/cgroup/battery<TAG>-<метка> как memory.max с memory.swap.max=0, а листовой ячейке достаётся весь CEIL, не делёжка на потоки. Каждый прибор идёт под timeout (база — 600 с, в пуле бюджет умножается на число потоков, при пересъёме соло — прежний).

logs/battery<TAG>-<метка>.log        # полный ход
logs/battery<TAG>-<метка>/red.list  # красные
grep "^=====" logs/battery<TAG>-<метка>.log   # сводка
  • rc=124 — прибор не влез в бюджет; rc=137 вместе с oom_kill>0 — память; rc=3 — сосед держит живой харнесс.
  • Пересъём соло (#135). Каждый красный прогоняется один, теми же аргументами: «погасло в одиночку» — мешали соседи, «устояло» — чинить правку или прибор.
  • Если вне потолка убито больше половины пула, прогон объявляется ИСПОРЧЕН и соло-суд недействителен: гнать заново на сытой машине.
  • Ворота байтов (#664). В конце сверяются контрольные суммы panel.py и index.html до и после: за прогон дерево не должно шелохнуться — иначе мерился не тот код, который стоит сейчас.

Приборы и красная база

Новая мера заводит свой прибор ccNN_<о чем>_test.py и обязана показать, что мерит именно правку: на байтах до неё те же ноги краснеют. Для этого в полигоне лежит сним панели этого выпуска:

python3 cc76_link_host_front_test.py --panel /opt/vpnpanel/panel.py
#   cc76: зелёных 54, красных 0

python3 cc76_link_host_front_test.py --panel backups/audit-2.16.1/gp/panel-head-854375d.py
#   cc76: зелёных 1, красных 29   — прибор мерит правку, а не погоду

Правильный прибор переживает обе проверки: зелёный на новых байтах и красный на прежних. Зелёный на прежних — значит нога ничего не измеряет, и её либо переписывают, либо снимают. Правка, которая роняет чужой якорь (ссылку на конкретную строку прежнего кода), примиряется открыто: якорь перепривязывают к новому инварианту и пишут в комментарии, чьим словом он снят.

Замок pre-push

В дереве лежит tools/git-hooks/pre-push. Он не даёт живым ключам уйти наружу: сверяет точные байты того, что есть на машине (имена полей берутся из объявления панели — _SECRET_KEYS, _SECRET_SUFFIX, _MV_PRIVATE), и печатает только имена источников, никогда сами значения. Расхождение панели и замка переснимает прибор cc36.

git config core.hooksPath tools/git-hooks     # поставить замок себе

Версия и выпуск

  • Версия — VERSION в panel.py:32; её печатает старт службы и её же ищет установщик.
  • Сводные выпуски — CHANGELOG.md заголовком ## [X.Y.Z] - YYYY-MM-DD; внутри — длинные русские записи с числами: контрольные суммы, число ног прибора, тег батареи, красный базовый коммит. Крупные правки текущего цикла живут в сообщениях коммитов в форме #NNN: что починено.
  • Релизный архив — veil.tar.gz с veil.tar.gz.sha256; рядом releases/ держит снятые архивы.
  • Коммит, тег, пуш и перенос на бой — шаги, которые делает владелец сервера, а не правка: локально дерево может жить незакоммиченным сколько нужно.
