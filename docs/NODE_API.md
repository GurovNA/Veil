# Node API — `/api/ext/*`

Панель умеет быть и мастером, и узлом. Как узел она принимает команды от другой
панели Veil (или от автономного `agent.py`) по короткому набору ручек
`/api/ext/*`, а как мастер — размещает своих подписчиков на чужих узлах.
Документ описывает сторону узла: то, что вызывает чужая машина.

## Модель доверия

* Доступ — скоуп-токен в `Authorization: Bearer <токен>` или в заголовке `X-Node-Token`.
* Токен выдаётся один раз и показывается один раз: в `config.json` лежит только
  его `sha256`, поэтому украденный конфиг токена не восстанавливает.
* Живёт не более `20` токенов. У каждого — метка и область: `read` или `write`.
* отзыв мгновенный: список токенов перечитывается на каждом запросе, удаления из
  него хватает, чтобы следующий вызов получил `401`.
* Ограничитель — `30` запросов с одного адреса за `10` секунд, сверху — `429`.
* Каждое событие пишется в аудит панели: `ext_denied`, `ext_rate_limit`,
  `node_token_add`, `node_token_revoke`, `ext_client_add` и так далее. В журнале
  остаётся только подсказка токена (первые `12` символов хеша), не сам токен.
* Транспорт — HTTPS на порту панели. Сертификат может быть боевой
  (Let's Encrypt) или панельной заглушкой; мастер в этом случае закрепляет
  отпечаток по правилу TOFU и токен не уходит на посредника.

## Как завести токен

Раздел «Федерация» в интерфейсе, либо та же ручка программы:

```
POST /api/nodes/tokens/add
{"label": "узловая панель А", "scopes": ["read", "write"]}
→ {"id": "…", "token": "…", "label": "…", "scopes": ["read", "write"]}
```

Ответ с токеном — единственный, где его видно. Отзыв — `POST /api/nodes/tokens/revoke`
с полем `id`. Обе ручки закрыты сеансом оператора: без правки настроек чужак
токен не создаст.

## Ручки только для чтения (scope `read`)

| Ручка | Что отдаёт |
|---|---|
| `GET /api/ext/status` | версию панели, uptime, живость `xray`, общее число клиентов и онлайн, трафик за сегодня, список входов (`proto`, `port`, число клиентов) и возможности узла (`caps`) |
| `GET /api/ext/inbounds` | тот же список входов, без агрегатов |
| `GET /api/ext/traffic?uuid=…` | трафик и онлайн **только тех клиентов, которых завёл этот токен** |

`caps` — честный самоотчёт узла: `clients_add`, `clients_update`,
`clients_delete`, `traffic`, `restart`.

## Ручки записи (scope `write`)

Все четыре читают тело запроса и возвращают `{"error": "…"}` с числовым кодом,
если что-то не так. Молча додумывать значение за вызывающего панель не стала:
пустое тело — `400`, а не «создай подписчика по умолчанию».

### `POST /api/ext/clients`

Создаёт подписчика на существующем входе.

| Поле | Обязательное | Правило |
|---|---|---|
| `name` | да | имя берется как есть, панель его не додумывает |
| `proto` | да | только вход, который на узле уже есть |
| `limit_gb` | нет | число гигабайт, `0` — без лимита; отрицательное и `NaN`/`inf` — `400` |
| `expiry_days` | нет | целое от `0` до `36500` суток, `0` — бессрочно |
| `reset_cycle` | нет | цикл сброса трафика |
| `max_devices` | нет | целое от `0` до `1000` |

Успех:

```json
{"client": {"uuid": "…", "name": "…", "proto": "reality",
            "sub_token": "…", "sub_url": "https://panel.example:8443/sub/…",
            "link": "vless://…"}}
```

Созданный клиент помечается `ext_owner` — идентификатором токена. Это и есть
граница видимости: другой токен его не увидит, не обновит и не удалит.

### `POST /api/ext/clients/update`, `POST /api/ext/clients/delete`

Работают по `uuid` и только над группой копий того же токена. Чужой `uuid` —
`404`, не «не нашёл, но ладно».

### `POST /api/ext/restart`

Перезапуск ядра на узле. Длинная операция, поэтому у вызова свой таймаут.

## Чего Node API не делает

* не трогает настройки панели, сертификаты, DNS, обход блокировок и входы;
* не отдаёт клиентов, подписчиков и ссылки, заведённые другим токеном или руками
  оператора;
* не принимает вызовы без токена — аноним не получает даже `404` по смыслу, только
  `401`;
* не заводит вход, которого на узле нет: протокол нужно включить на самом узле.

## Сторона мастера

Мастер ходит на узел тем же набором (`_node_call` в `panel.py`), закрепляет
отпечаток сертификата узла по TOFU и проверяет адрес узла SSRF-границей —
внутрь локальной сети, на метаданные облака и на loopback запрос не пойдёт.
Зеркало своего клиента на узле добавляется в ту же подписку, поэтому человеку
не нужна вторая ссылка: `/sub/<token>` отдаёт все его входы сразу.
