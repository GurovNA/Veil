# Архитектура Veil

Карта для того, кто открыл репозиторий впервые и не собирается читать
`panel.py` целиком. Названы файлы, функции и границы — без строк, потому что
строки в этом дереве разъезжаются каждый выпуск.

## Форма выпуска

Панель — один файл `panel.py` (около `39 000` строк) на чистой стандартной
библиотеке Python. `pip` на сервере не нужен: установка — это `install.sh` на
голую Ubuntu, а наружные модули (`cryptography`, `yaml`) берутся на месте внутри
`try` и честно отказывают, если их на коробке нет. Номер версии — константа
`VERSION` в том же файле; выпуск собирается вокруг одной продуктовой правки.

Рядом лежат:

| Файл | Что это |
|---|---|
| `install.sh` | установка, переустановка и удаление; шаги `0`–`6`, есть `--step N` и `--dry-run` |
| `agent.py` | автономная нода: только stdlib + `xray` + `openssl`, свой набор ручек `/agent/*` |
| `teleconf_witness.py` | свидетель: ловит, кто переписывает конфиг `telemt`, и пишет только `comm`/`exe`/`pid` — никогда `cmdline` |
| `migrate_from_old_db.py` | перенос с чужих панелей |
| `index.html`, `i18n.json` | морда и словарь трёх языков (`en`, `fa`, `zh`; русская строка — ключ) |
| `veil.tar.gz` + `.sha256` | релизный архив и его контрольная сумма; установщик сверяет архив до распаковки |

## Где что живёт на сервере

| Путь | содержимое |
|---|---|
| `/opt/vpnpanel` (`BASE`) | рабочий каталог панели |
| `config.json` | настройки оператора: порог прав, домен, токен бота, ключи доступа |
| `state.json` | входы и подписчики — то, что видит глаз панели |
| `sessions.json`, `passkeys.json` | живые сеансы и ключи входа |
| `logs/` | журнал панели, `traffic_days.json` — суточные счётчики трафика, журнал аудита |
| `certs/live/…` | сертификаты: и боевой выпуск Let's Encrypt, и панельная заглушка `CN=Veil` |
| `media_route.json` | состояние медиа-пути через туннель |
| `/usr/local/etc/xray/config.json` | конфиг ядра, который пишет панель; рядом `hy2_cert.pem`/`hy2_key.pem` |
| `/etc/telemt/telemt.toml` | конфиг MTProto-прокси |
| `/etc/nginx/veil-mux-stream.conf` | SNI-мюкс: карта «имя → бэкенд на петле» |
| `/opt/veil-zapret2`, `/etc/veil-zapret2` | обход блокировок и его конфигурация |

Приватное состояние — `config.json`, `state.json`, снимки ключей — не уезжает ни
в переносе (`_MV_PRIVATE` в панели), ни в индексе git (`.gitignore`). За этим
следят и приборы: `tests/test_tree_hygiene.py` ловит приватный файл в публичном
дереве.

## Порты

Панель держит список зарезервированных (`_RESERVED_PORTS`): `80` занят
nginx/Let's Encrypt, `18080` — веб `telemt`, `9091` — его API, `7443` — слушатель
MTProto. Каждый протокол имеет заводской порт (`reality` на `20443`, `ws`‑входы на
`11443`–`21443`, `hysteria2` на `27443`, WireGuard на `28443`, AmneziaWG на
`28444`), а на `443` вход переводит явно включённый SNI-мюкс — сама панель `443`
не занимает.

## Путь одного изменения

Почти всё, что делает интерфейс, идёт одной дорогой:

1. ручка `POST /api/…` проходит `_perm_gate` (матрица «роль → ручка») и читает тело;
2. правка ложится в словарь состояния;
3. `_apply_state(st)` собирает конфиг ядра и один раз вызывает `_validate_and_apply`;
4. валидация — это `xray run -test` на временном файле: ядро само говорит, примет ли оно конфиг;
5. `_xray_apply_gate` не даёт двум изменениям Xray в одну секунду дать два рестарта;
6. `_write_xray` пишет конфиг, состояние сохраняется, ядро перезапускается один раз;
7. `_wg_sync`/`_awg_sync` разносят ключи по интерфейсам ядра, `_mux_apply` перекладывает входы под `:443`;
8. событие идёт в аудит, оператор получает ответ с причиной, а не молчаливый `200`.

Последовательность когда-то была рукописной в полутора десятках мест, и это
дорого платило: конфиг коммитился до проверки, а `xray run -test` делался дважды.
`_apply_state` существует, чтобы этот путь был один.

## Соседи

* **Xray** — ядро VPN. Панель его единственный владелец конфига; говорит с ним
  только файлом и `systemctl`, статус судит по юниту и по счётам живых входов.
* **telemt** — MTProto-прокси. Панель кладёт ему конфиг и читает Local API на
  `127.0.0.1:9091` (`/v1/config`, `/v1/users`, `/v1/stats/dcs`,
  `/v1/stats/users`, `/v1/runtime/gates`). Отдельный свидетель следит, кто ещё
  трогает `/etc/telemt/telemt.toml`.
* **nginx** — SNI-мюкс по `ssl_preread`: один `443` отдаётся веб-фронту, VPN-входу
  и MTProto по имени, которое клиент шепчет в handshake. Мюкс переносит вход на
  петлевой порт, поэтому ссылка смотрит наружу: `_pub_port` и `_pub_host` правят
  порт и хост в ссылке, чтобы человек не получил `127.0.0.1:4443`.
* **WireGuard / AmneziaWG** — интерфейсы ядра (`veilwg`, `awg0`), ключи разводит
  панель, конфиг `.conf` собирается на выдаче.
* **zapret2** — обход блокировок отдельным юнитом; панель включает и выключает его
  целиком и честно сообщает, если компонента на коробке нет.
* **Cloudflare WARP** — окна, которые уводят часть адресов через веер Cloudflare.
  Механика общая (`_tw_*`), окна различаются числами и словом в настройках:
  медиа-путь Telegram — `tgw0`, таблица `203`, приоритеты `100..108`, порог входа —
  процент потерь на адресе узла, путь снимается сам, если становится хуже, чем без
  него; TikTok — `tkw0`, таблица `204`, `200..456`, обход `190` (метка `0x2d`);
  YouTube — `ytw0`, таблица `205`, `600..679`, обход `590` (метка `0x2e`); Игра —
  `gmw0`, таблица `206`, `700..`, обход `690` (метка `0x2f`). Исключения `Gemini`
  сидят ниже всех окон (`110..173`). У каждого окна свой аккаунт, свой кулдаун
  замены и своя карточка: выключение одного не гасит другие. Адреса, не названные
  в списке окна, перемаршрутизируются не могут — правило ставится только на подобранный блок.

## Подписки и ссылки

Одна ссылка `/sub/<token>` на подписчика. Формат угадывается по `User-Agent` или
по явным `?format=`: base64-список для v2rayNG/NekoBox/Hiddify, JSON для sing-box,
ссылочный формат INCY. Заголовки `subscription-userinfo` несут остаток трафика и
срок. Ограничение числа устройств считается по токену подписки, а не по IP:
человек с несколькими телефонами и с прокси не должен ловить отказ.

## Федерация

Панель умеет быть узлом для другой панели (Node API, `/api/ext/*`) и мастером,
который размещает своих подписчиков на чужих узлах. Токены скоупнуты
(`read`/`write`), хранятся хешем, отзываются мгновенно; адрес узла проходит
SSRF-границу, а отпечаток его сертификата закрепляется по TOFU. Подробно —
[NODE_API.md](NODE_API.md).

## Границы безопасности

Сеанс с 2FA и passkeys, матрица прав на каждую ручку, рамка CORS по чужому
`Origin`, ограничитель частоты на внешние ручки, SSRF-граница на всех выходах по
адресу, который ввёл оператор, журналирование с вычисткой секретов
(`_audit_redact`), приватные файлы вне переноса и вне индекса. Проверка этого
списка — не обещание: часть границ стоит в наружных приборах `tests/`, остальное
— в приватной батарее, которая в репозиторий не выкладывается.

Отдельная граница — собственная анонимность репозитория. Всякий литерал адреса в
открытом дереве обязан быть либо служебным, либо чужим и названным в реестре
прибора; адресам наших коробок в нём места нет, как и отпечаткам их `ssh`-портов:
по открытому отпечатку чужой сканер опознаёт узел, не глядя на адрес. Поэтому наш
адрес нельзя прятать и в сам реестр — на это стоит отдельная нога.

## Как это проверяется

```bash
python3 -m unittest discover -s tests -t tests
```

Приборы наружного CI: компиляция исходников и объявленный минимум Python,
запрет не-stdlib импортов, целостность релизного архива и его дайджеста,
поведение сверки в установщике, паритет словаря интерфейса, разбор чужих ссылок
и подписок, SSRF-граница, мера самоподписи, гигиена дерева. CI —
[`.github/workflows/ci.yml`](../.github/workflows/ci.yml).
