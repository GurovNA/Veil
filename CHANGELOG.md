# Changelog

All notable changes to Veil — VPN Panel will be documented in this file.

## [2.13.0] - 2026-09-25

**Переезд на новый VPS в один экран: панель сама ставит себя на чистый хост, переносит всё «порт-в-порт» и переключает домен — ссылки подписчиков не меняются вообще. Плюс свой фронт-домен для MTProto, устройства «как приложение, а не как IP» и вход по Face ID по умолчанию.**

- **🚚 «Переезд» (вкладка для владельца).** Вписываешь IP/логин/пароль нового VPS — и панель делает всё сама: порок за порком проверяет новый хост и показывает, «кем занято» (SSH-демон не трогает никогда); при явном согласии принудительно забирает занятые порты (stop+mask); пакует **всё состояние** — подписчиков, сессии, passkeys, баны, устройства, ключи Reality/HY2, секреты и пользователей telemt, конфиги nginx с сайт-масками, сертификаты Let's Encrypt с приватными ключами, аватары, geo-правила — и переустанавливает Veil на новом хосте **на тех же портах**, поэтому ни одна выданная ссылка не ломается. Дальше — самопроверка снаружи (порты слушаются, панель отвечает), переключение DNS (Cloudflare A + wg-эндпоинт, dynv6 v4/v6 или пошаговая ручная инструкция) — сразу или по расписанию (например, в 3:00 МСК, можно с авто-пенсией старого хоста). Старый хост «пенсионируется» только отдельной явной кнопкой. Защита от «двух хозяев»: пока переезд не завершён, DDNS-самообновления и ротация приостановлены, Telegram-бот на новом хосте молчит, пока не нажмёшь «Переезд завершён». Каждое действие пишется в журнал на диске — прерванный переезд продолжается с того же места, а не с начала. В карточке статуса — крупный адрес новой панели с кнопкой «Скопировать»; адрес дублируется в Telegram-уведомлениях.
- **🎭 Сайт-маска TLS-F: свой фронт-домен для MTProto.** Cloudflare DNS → сертификат Let's Encrypt (DNS-01) → заглушка на :443 → telemt `tls_domain` → ротация facade-секретов → автоматические sniffing-исключения во всех xray-inbound'ах. Домен вшивается в `tg://`-ссылку при выдаче, поэтому старые ссылки старых фронтов продолжают работать — плавный перевод клиентов без перевыпуска. На вкладке Telegram — карточка «🌟 Главная ссылка Telegram» (находит клиента со свежим фронтом, Копировать/QR/Открыть) и чипы «🏠 свой фронт» у клиентов.
- **🧪 Самопроверка «MTProto под VPN» + штормовой фикд.** Карточка на вкладке Telegram жмёт facade-рукопожатие на публичный порт по v4 и v6, проверяет исключения фронтов и живость сайт-маски. Найдена и закрыта туннельная петля (hairpin): без исключений destination подменялся на SNI фронтов — Akamai-шторм из безответных SYN и упор в SYN-лимит; лимит veil_synfix теперь зеркалится и на IPv6 (reject через icmpv6 no-route).
- **📱 Устройства — приложение, а не IP.** Запись устройства в журнале `/p` теперь склеивается по устойчивому «токену установки» из User-Agent (Happ и клиенты той же схемы): переехал с Wi‑Fi на 4G — осталось то же устройство (в карточке — подсказка «·IP×2»). Лимит `max_devices` по журналу Xray научился роуминг-слиянию: новый IP достаётся самому давно «затихшему» устройству того же клиента; бан — только при устойчивом (>2 мин) превышении и только по самому молодому устройству. Попутно ожил мёртвый механизм: Xray 26.x пишет email в формате «email: &lt;uuid&gt;», и парсер не видел ни одного подключения — лимит устройств и «устройства за 15 мин» снова считаются (смещение чтения журнала переживает рестарт, двойного счёта нет).
- **🔑 Passkey по умолчанию.** Если к панели привязан ключ, экран входа сразу предлагает большую зелёную кнопку «🔑 Face ID / Touch ID»; логин/пароль свёрнуты в «Войти паролем» (подсказки на en/fa/zh). Проверка наличия ключей — недорошущим эндпоинтом (список наружу не отдаётся).
- **🧲 Лимит устройств для ссылки TG-прокси.** В карточке клиента прокси — выбор «📱 Лимит устройств» (без лимита / 1..10): сколько разных адресов может одновременно пользоваться ссылкой; новых подключений сверх лимита telemt просто не принимает. Статус — «онлайн: N / лимит M».
- **📊 «Чем вы пользуетесь» (C8).** На `/p` — разбивка по протоколам за 7 дней с «последним заходом» (RU/EN/FA/ZH), в карточке подписчика админки — одноимённая раскладка.
- **📣 Самопривязка смены адреса (B5).** Панель раз в минуту сверяет хост в ссылках подписок: сменился (переезд, DDNS, хоп) — подписчики с Telegram получают push «новый адрес + кнопки», на `/p` неделя баннера «обнови подписку», админам — сводка; ссылки `/sub` пересобираются сами.
- **🤖 Кнопки бота подписчика.** «➕ Прокси в Telegram» в один тап (`tg://proxy` / `tg://webproxy`) и «💳 Продлить» — с тарифами оплаты (или запросом админу при выключенных платежах); алерты «80 %/истекает» с кнопкой «📱 Страница подписки»; команды `/proxy` и `/renew`.
- Мелочи из 2.12.1: MTProto dual-stack (iOS под VPN больше не теряет прокси), WG/AWG исключают и свой IPv4, и IPv6, профиль маршрутизации INCY в подписке диплинк-формой, `domainsExcluded` для facade-фронтов.

## [2.12.0] - 2026-09-25

**Веб-прокси наконец подключается, а Telegram-прокси больше не конфликтует с VPN: панель сама вносит адрес сервера в «исключения» всех клиентов — автоматически и без напоминаний.**

- **🌐 Починен Web Proxy.** Конфиг nginx панели переопределял политику безопасности telemt, и из-за этого скрипты страницы-моста (у них одноразовые ключи-nonce) блокировались: страница открывалась, но «не подключалась». Переопределение убрано; включён и автовыбор транспорта: под VPN поддерживающие клиенты сами уходят на WebSocket, а iPhone остаётся на HTTPS — веб-прокси стабильно подключается и с включённым VPN, и с выключенным.
- **🧲 MTProto работает, не требуя выключать VPN.** Telegram-прокси указывает на этот же VPS, и при включённом VPN трафик шёл туннелем обратно на тот же сервер — петля, «нет соединения». Раньше это чинили руками: находили IP сервера и вносили его в «direct». Теперь панель делает это сама:
  - в конфигах `.conf` WireGuard и AmneziaWG адрес сервера исключён из туннеля;
  - в полном конфиге sing-box — правила «напрямую» для адресов и домена панели;
  - клиентам **Happ** и **INCY** вместе с подпиской приходит профиль маршрутизации, где IP-адреса и домен панели уже в «напрямую» (в Android-Happ это поле «исключительные маршруты» — теперь оно заполняется само); профиль отдаётся даже с выключенным обходом РФ — только чтобы разорвать петлю.
  - **панель сама проверяет, какой сейчас адрес у сервера** (через внешний сервис и по собственным DDNS-записям): если IP VPS сменился, исключение обновится при следующем обновлении подписки — вносить что-либо вручную не нужно.
- **📡 WireGuard перестал «загораться и падать» в мобильных сетях.** Панель заводит в dynv6/Cloudflare отдельный IPv4-only эндпоинт `wg.<домен>` (без AAAA-записи): мобильный IPv6-транспорт рвёт WG-сессии. IPv6-адреса внутри туннеля теперь выводятся из IPv4 — никакая миграция настроек не нужна.
- **🗺 Геобазы стали лёгкими.** Панель обрезает зеркальные файлы 18/73 МБ до нужных кодов и раздаёт сама: телефоны успевают скачать их без таймаута, и обход РФ включается в Happ/INCY автоматически.
- **🚀 Первый запуск «из коробки».** Установщик довершает настройку Telegram-прокси, а свежая панель без единого клиента сама заводит личную подписку владельца и отправляет ссылку в Telegram-бот.
- **🛒 Магазин.** Публичная страница тарифов `/shop` (ЮKassa / CryptoBot / ручная выдача — с автоматическим продлением и пополнением лимита), тарифы привязываются и в боте; аватарки подписчиков теперь отдаются отдельными файлами — личный кабинет стал легче.
- **🔒 Приватность веб-прокси.** nginx перестал записывать обращения к странице-мосту: в её адресе живёт одноразовый ключ подключения (`?bridge=…`), а в логе оседали ещё и IP клиентов. Теперь журнал этого vhost выключен — как рекомендует сам Telemt.
- Мелочи: после «сменить секрет» в ссылке проставляется реальный публичный порт; правки руководств и переводов.

## [2.11.0] - 2026-09-24

**Личный кабинет с своей аватаркой и Telegram-бот, который работает и с подписчиками.**

- **🪪 Аватар подписчика.** На личной странице `/p` появилась кнопка-камера: подписчик ставит своё фото (обрезается в квадрат прямо в браузере), одной кнопкой рядом убирает. Проверяется настоящий формат (PNG/JPEG/GIF/WebP) и размер (до 160 КБ); хранится отдельно от конфигов, наружу не отдаётся — показывается только самому подписчику на его странице.
- **🤖 Бот для подписчика (RU/EN/FA/ZH).** Обычный пользователь без прав администратора отправляет боту ссылку своей подписки — и бот привязывает её к его Telegram. После этого: «📊 Моя подписка» (статус, срок, трафик), «🔑 Ссылка», «📱 Приложения» (быстрая ссылка на личную страницу), «🔗 Отвязать» и выбор языка; команды /start, /status, /link, /apps, /unsubscribe. Администраторы видят прежнее служебное меню.
- **🔔 Напоминки лично подписчику.** При 80% трафика и за 3/1 день до окончания подписки уведомление приходит не только владельцу панели, но и самому подписчику — на языке, который он выбрал в боте.
- **📥 Исправление импорта баз.** На iPhone/iPad в окне «Импорт → База» файл `.db` был не выбрать (серый в iCloud): убран лишний фильтр типов, безопасность проверки не пострадала — панель по-прежнему читает только настоящие sqlite-базы.
- **✍️ Честный текст про перенос.** В предпросмотре импорта больше не обещается, что ссылки подписчиков «продолжат работать» — вместо этого прямо сказано, что старые ссылки умрут после остановки исходной панели, и подписчикам нужно один раз выдать новые (лучше сразу ссылку-подписку).

## [2.10.0] - 2026-09-24

**Починенные MTProto-ссылки в подписках, бренд и кнопка связи в Happ, честный счёт клиентов по портам, настоящие логотипы приложений в кабинете и ручные точки отката.**

- **🔧 Исправлены битые ссылки MTProto.** Панель отдавала клиентам служебный порт 18080 (доступный только с самого сервера) вместо публичного порта прокси — подписки и кнопки в личном кабинете перестали «ломаться» при выдаче: ссылка теперь всегда собирается с реальным публичным портом (кэшируется на 30 секунд, не тормозит раздачу).
- **📲 Личный кабинет `/p` стал полнее.** У подписчика появились кнопки «MTProto · Telegram» и «Web-прокси · Telegram» — прокси для Telegram добавляются одним тапом, как и остальные протоколы; ссылки переводятся на язык кабинета (RU/EN/FA/ZH).
- **🏷 Брендинг подписки в Happ.** Новые поля в «Настройки подписки»: **«Бренд в приложениях»** (до 25 символов — название подписки в клиентах, по умолчанию — имя клиента) и **«Кнопка связи в клиентах»** (support-url: ссылка на поддержку; если указать t.me — в Happ справа появляется иконка Telegram). Также передаётся ссылка на личный кабинет (иконка слева) и корректные счётчики трафика/срока.
- **🖼 Настоящие логотипы приложений в кабинете.** Каталог «Где скачать» показывает официальные иконки 19 приложений (App Store, Google Play, GitHub) вместо цветных букв; если иконку найти не удалось — аккуратная буквенная плитка. Панель раздаёт их по адресу `/appicons/` с недельным кэшем; добавлен и `/favicon.ico` панели.
- **📊 Дашборд: честная математика.** Клиенты считаются отдельно для каждого порта группы протоколов (раньше «3 клиента» на одном порте скрывали сумму по нескольким inbound-ам); подпись «1 клиент / N клиентов» вместо «Nкл».
- **📦 Версии и откат.** Блок показывает текущие версии панели, Xray и telemt и позволяет кнопкой **«Создать точку отката»** вручную сохранить пару panel.py+index.html (хранится 7 последних, как и автоматические копии перед обновлением).
- **🧹 Мелочи и база.** Кнопка «Выйти из панели» переехала на главный экран (в классическом интерфейсе); стартовая карточка «Я тут впервые» свёрнута по умолчанию; в проверке А-записей больше не виден технический `<br>`; починен пустой экран после свайпа между вкладками на телефоне.

## [2.9.0] - 2026-09-24

**Оплаты на странице подписчика, вход по Face ID / Touch ID, вкладка «Логи», операторы с правами и перевод всего интерфейса, бота и страниц подписки.**

- **🔑 Вход по ключу устройства (passkeys).** Реализован собственный WebAuthn-движок на стандартной библиотеке — Face ID / Touch ID на iPhone и Mac, Windows Hello, отпечаток на Android. Ключ хранится в защищённом чипе устройства и никогда его не покидает; панель проверяет подпись, происхождение и счётчик (защита от клона). Ключи — до 12 на пользователя, со списком и удалением во вкладке «Безопасность»; пароль остаётся запасным входом. На голом IP браузеры ключи не сохраняют — панель честно подсказывает открыть её по домену.
- **💳 Приём оплат прямо на `/p`.** Подписчик выбирает пакет (трафик/срок), платит картой через ЮKassa, криптой через CryptoBot, через «свою кассу» (HMAC-подписанный API для интеграции своего платёжного шлюза) или «вручную» (заявка — админ подтверждает). Поступление само продлевает лимит и срок клиента; все платежи и возвраты — в журнале и в отчётах Telegram-бота. Провайдеры настраиваются владельцем, ключи хранятся только на сервере.
- **📖 Вкладка «Логи»** — журналы служб (Xray, telemt, nginx, панель, systemd-journal) в браузере, с фильтром по службе, поиск и хвост в реальном времени. Больше не нужен SSH, чтобы посмотреть, почему «не коннектит». История входов починена и тоже переведена.
- **👥 Роли: операторы с настраиваемыми правами.** Владелец заводит рабочие аккаунты и включает им только нужные разделы (клиенты, нода, логи…). Каждому оператору — свои passkey и 2FA; действия пишутся в общий аудит с именем оператора.
- **🌍 Перевод завершён целиком**: страницы подписки `/p` и `/sub` (автоопределение языка по браузеру + переключатель RU/EN/FA/ZH), Telegram-бот (`/lang`, язык берётся из профиля Telegram), установочный `install.sh` (EN-сообщения при английной локали) и новые инструкции «простым языком» для всех разделов. Языковой переключатель — аккуратный квадратик 2×2, флаги больше не пропадают в Windows.
- **📲 Подписки для клиентов стали понятнее.** WireGuard и AmneziaWG отдаются однострочными ссылками `wireguard://` и `amneziawg://` — они импортируются в Shadowrocket, Happ, NekoBox из подписки без танцев с .conf. У каждого клиента появилась кнопка **«🧩 Все протоколы»**: клиент, созданный под один протокол, одним кликом добавляется во все включённые протоколы — с теми же лимитами и сроком, и сразу попадает в свою подписку. Страница «Устройства» показывает, с каких телефонов/клиентов качают подписку, и позволяет забыть лишние.
- **🛠 Ноды и агент**: agent.py v1.1.0 — удалённая перезагрузка ядра на ноде, бан клиентов, ограничения и честная отчётность возможностей; ext-API панели-ноды принимает эти команды под теми же скоуп-токенами. В карточках нод — инструкция «куда тыкать» и иконка двойного прыжка.
- **⚡ Скорость и чистота сервера.** Страница панели теперь приходит gzip'ом (~1 МБ → ~300 КБ) и при повторном открытии отдаётся пустым 304 — загрузка почти мгновенная. Рост логов ограничен: syslog режется при 100 МБ и сжимается, journald — жёсткий лимит 150 МБ. Журналы панели (аудит, истории) и лишние файлы давно имели лимиты — все проверены.
- Мелочи: шапка личного кабинета `/p` приведена в порядок (статус и языки больше не наслаиваются), текст «Veil — VPN Panel» используется в формальных местах (README, релизы), интерфейс остаётся просто Veil.

## [2.8.0] - 2026-09-24

**Панель на трёх языках, читаемость в любой теме, настоящий мобильный интерфейс и пошаговые инструкции «куда тыкать».**

- **🌍 Мультиязычность интерфейса: EN / FA / ZH.** В шапке появился выбор языка (Русский / English / فارسی / 中文) — выбор запоминается в браузере, для фарси интерфейс разворачивается справа налево (RTL). ## [2.7.7] - 2026-09-23

**MTProto «из коробки» на хостах с включённым web-прокси — честная починка публичного listener'а вместо переноса fake-TLS фронта.**

- **Корень проблемы** (по докам telemt `docs/Architecture/Fronting-splitting/TLS-F-TCP-S.ru.md`): маскировочный fake-TLS (`censorship.mask`+`mask_port`) — это **TCP-splitting upstream**, куда telemt **перенаправляет non-MTProto** соединения; а сам MTProto слушает `[server] port` **через `[[server.listeners]]`**. С telemt 3.5+ массив listeners — **исчерпывающий**: если в файле есть хоть один `[[server.listeners]]` (например, `ip=127.0.0.1 transport="web" port=18080`, который добавляет панель при включении web-прокси), и среди них нет публичного `transport="mtproxy"`, — telemt **не биндит `[server] port` вообще**, и `tg://proxy`-ссылка ведёт в никуда. Именно это ломалось на «грязных» хостах после включения веб-прокси (панельный баг, который мы до этой версии пытались лечить переносом `mask_port` — этот путь был принципиально неверным).
- **Панельная фича «Оживить MTProto» переписана под listeners**: `_tg_mp_preview/_tg_mp_apply/_tg_mp_revert` теперь читают и правят блок `[[server.listeners]] ip="0.0.0.0" port=<[server] port> transport="mtproxy"`, а не `censorship.mask_port`. Вставка — сразу после последнего существующего listeners-блока; при удалении — вырезается ровно по маркеру `# Veil:MTProtoListener`. apply: пишет блок → systemctl restart telemt → ждёт, пока `_tg_mtproto_info` покажет `up=true` на нужном порту → при неудаче **полный откат конфига** (backup toml + restart). revert: вырезает блок, возвращает `[server] port`, перезапускает, честно говорит, кто теперь держит порт.
- **Панель больше не ломает MTProto при включении web-прокси** (`_tg_web_enable`): если `[[server.listeners]]` ещё нет, и мы его добавляем для `transport="web"`, тут же добавляем и публичный MTProto-listener на `[server] port` (или `7443`), иначе он «исчезает» по той же исчерпывающей семантике массива.
- **Честная диагностика**: `_tg_mtproto_info` возвращает `{port, mask, mask_port, server_port, up, proc, has_public_listener, note}`; панель больше не путает «порт, на который смотрит fake-TLS» с «портом, на который должен подключаться MTProto-клиент». Ссылка `tg://proxy` в UI/JSON строится вокруг реального публичного MTProto listener'а (`port=<real>`).
- **UI вкладки «Proxy»**: карточка «🔌 Публичный MTProto listener» вместо «Порт MTProto (fake-TLS фронт)» — показывает отдельно `[server] port` и наличие публичного listener'а, кнопку «⚡ Оживить MTProto на :PORT» с честным описанием того, что именно будет добавлено (`[[server.listeners]] ip=0.0.0.0 port=N transport=mtproxy`), и «⟲ Откатить listener, добавленный панелью».
- **Проверено на живом хосте A** (dynv6 `926923.v6.navy`, nginx на :443, telemt 3.5.7 с `mask=true mask_port=443 tls_domain=my.aeza.ru`, `[server] port=7443`): до фикса — `ss` пуст на :7443, ссылки вели в никуда; после apply — `LISTEN 0.0.0.0:7443 users:(("telemt"...))`, `openssl s_client -connect 212.113.102.6:7443 -servername my.aeza.ru` отвечает фронтом `CN=*.aeza.net` (корректный fake-TLS), панель выдаёт рабочие `tg://proxy?server=926923.v6.navy&port=7443&secret=ee...`. Полный цикл preview → apply → revert → apply отработал без артефактов.

**Второй срез мюкса :443 — разрушительный «включить/откатить» для cert-TLS VPN на «грязном» хосте, где :443 уже занят.**

- **T-мюкс по SNI (`_mux_apply`/`_mux_revert`, кнопки «Применить/Откатить»)**: теперь из панели можно забрать :443 под nginx и развести его по SNI через `stream + ssl_preread`: наш домен веб-фронта → прежний веб-бэкенд (переезжает на `127.0.0.1:8445`), отдельный SNI-поддомен VPN → xray cert-TLS на loopback, default/пустой SNI → веб.Reality не затрагивается (у него общий SNI с сайтом-прикрытием — через `ssl_preread` его нельзя отделить от реального посетителя, поэтому мюкс работает только для cert-TLS inbound'ов с нашим сертификатом). Все изменения nginx.conf/веб-конфига и inbound'а xray предварительно бэкапятся, проверяются через `nginx -t` и `xray run -test`, при любой неудаче **полностью откатываются**.
- **Безопасный откат**: кнопка «Откатить» возвращает nginx.conf и веб-конфиг из бэкапов, восстанавливает прежние `listen/port/сертификат` inbound'а, гасит временные stream-файлы и оставляет панель/nginx/xray активными. Проверено на «жертвенном» VPS: apply → 443 занимает nginx, `curl`/`openssl s_client` по обоим SNI уходят в правильные бэкенды; revert → хеш `nginx.conf` совпадает с довоенным, лишние листенеры исчезают, inbound возвращается на исходный порт.
- **Честные блокировщики в предпросмотре (`_mux_preview`)**: перед применением панель реально (а не по `nginx -V`) проверяет доступность stream-модуля — на Ubuntu с `--with-stream=dynamic` его даёт пакет `libnginx-mod-stream`, подключаемый через `modules-enabled/*.conf`; если модуль не грузится, предлагается `apt-get install -y libnginx-mod-stream`, а не ложное «всё готово».
- **Исправления по ходу прогона**: self-signed-сертификат мюкса больше не падает на OpenSSL 3.x (синтаксис `-newkey ec:prime256v1` → `-newkey ec -pkeyopt ec_paramgen_curve:prime256v1`); детект уже загруженного stream-модуля учитывает, что `modules-enabled/*.conf` — симлинки (`grep -r` их не обходит → `grep -R`), иначе вставлялся дублирующий `load_module` и `nginx -t` падал; при провале `nginx -t` откат теперь сохраняет и `state.json` (раньше inbound оставался «прикован» к мёртвому loopback-порту).
