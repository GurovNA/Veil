# Veil

VPN-панель + Telegram MTProto прокси с DPI-фиксом.
Установка одной строкой на Ubuntu 22.04 / 24.04 / 26.04.

Актуальная версия: **v2.0.3**

## Установка

  bash <(curl -fsSL https://raw.githubusercontent.com/GurovNA/Veil/main/install.sh)

В конце скрипт выведет URL панели, логин и пароль (сгенерирован автоматически).
Логин и пароль можно сменить в разделе Безопасность панели.

## Что нового в v2.0.3

- **Hysteria2 и WireGuard прямо в Xray.** Две новые группы протоколов «Hysteria2» (UDP 27443) и «WireGuard» (UDP 28443), реализованы целиком на Xray-core — отдельного демона не нужно.
  - **Hysteria2** (QUIC/UDP): автоматический самоподписной TLS-сертификат (генерируется при первом включении), masquerade-прокси на домен панели (активный провайдер видит лишь HTTP/3-трафик к текущему домену). Ссылка — `hy2://` с параметрами `sni` и `insecure=1` (самоподписной сертификат), QR-код для мобильных клиентов (Hiddify, v2rayNG, NekoBox).
  - **WireGuard** (userspace UDP): пара x25519-ключей на сервер, каждому клиенту — свой ключ и адрес из сети `10.10.0.0/32` (10.10.0.2, 10.10.0.3, …). Вместо ссылки — готовый `.conf`-файл (кнопка ⬇ «Скачать .conf»), который открывается официальным WireGuard-приложением / WireGuard-клиентом.
  - Оба протокола получают клиентов так же, как остальные: «+» на карточке протокола → ссылка/QR сразу. Счётчик, переименование, удаление, трафик — всё работает как обычно.

## Что нового в v2.0.2

- **Fingerprint перенесён в настройки inbound.** Блок «Отпечаток TLS» удалён из вкладки «Настройки» — теперь отпечаток настраивается прямо в диалоге «Настройки inbound» (кнопка ⋯ на карточке протокола → «Настройки inbound»). Вместе с портом и SNI — всё в одном месте.
- **Валидация SNI: нельзя сломать VPN несуществующим доменом.** При смене SNI панель проверяет DNS-резолв и TCP-доступность порта 443. Если домен не найден в DNS или не отвечает — изменение отклоняется с ясным сообщением (ранее панель молча переписывала `dest = sni:443`, и REALITY-хендшейк падал на несуществующем домене).

## Что нового в v2.0.0

- **Карточки протоколов стали строже и нагляднее.** Кнопка «⋯» (открыть QR-код) теперь симметрично сбалансирована: имя протокола и счётчик клиентов расположены по центру строки, а «+» и «⋯» — зеркально по краям. Карточка **shadowsocks-2022 по умолчанию свёрнута** и раскрывается по клику на «+» (как и остальные протоколы — раскрытие/сворачивание работает по клику в любом месте строки).
- **Web Proxy (nginx :443 → telemt web) устанавливается прямо из панели.** Новый блок на вкладке «Telegram прокси»: панель показывает состояние портов 80/443 и подсказывает причину, если установка невозможна:
  - порт 80 или 443 занят — «установка станет доступна после освобождения», кнопка установки скрыта;
  - нет домена или DDNS — «внеси его во вкладке Сайт (раздел DDNS/dynv6)»;
  - домен задан и порты свободны — появляется кнопка «Установить Web Proxy (nginx)».
  Установка ставит nginx через apt (если отсутствует), генерирует `/etc/nginx/conf.d/webproxy.conf` (TLS :443 → 127.0.0.1:18080) с сертификатом панели (Let's Encrypt, либо выпущенным для домена, либо самоподписанным), проверяет конфиг `nginx -t` и включает/перезапускает службу. Также доступен GET `/api/webproxy/status` и POST `/api/webproxy/install`.
- **Обновление и откат telemt на вкладке «Telegram прокси».** Блок «Telemt: обновление и откат»: текущая версия, список всех доступных версий с меткой «(pre)» для prerelease, кнопка «Сменить версию» (скачивание, проверка запуска бинаря, бэкап текущего, перезапуск telemt) и список бэкапов для отката на прошлую версию.
- Web Proxy-блок на вкладке «Telegram прокси» дополнен статусом установки nginx-прокси поверх telemt web.
- **Отпечаток TLS (fingerprint) настраивается из панели и по умолчанию firefox.** Новый раздел «Отпечаток TLS (fingerprint)» во вкладке «Настройки»: выбор из firefox/chrome/safari/ios/android/edge/randomized/random. Значение подставляется в ссылки всех TLS-протоколов (reality, xhttp, ws/grpc, trojan, vmess) вместо зашитого chrome. По умолчанию — **firefox** (с ним Reality-рукопожатие стабильнее всего; с chrome оно падает на части клиентов).

## Что нового в v1.8.5

После продления обновляются TLS-контекст панели и рестартует Xray.

## Что нового в v1.8.4

- **Починен вход: страница больше не «выкидывает» на логин после обновления (F5).** Причина была не в сессии: inline-JS панели выполнялся раньше, чем в DOM появлялся элемент `#qrModal` (он объявлен после закрывающего `</script>`), из-за чего top-level `document.getElementById('qrModal').addEventListener(...)` падал с `TypeError` на `null`. Весь скрипт останавливался **до** вызова `refresh()`, панель не показывалась даже с валидной сессией (вчера исправленный код проверялся только в тестовом окружении, где мок `getElementById` всегда возвращал элемент — в реальном браузере этого элемента ещё нет). Обработчик клика перенесён на делегирование через `document`, он больше не зависит от порядка появления элемента.

## Что нового в v1.8.2

- **Убран VLESS + SplitHTTP + TLS (self-signed).** Первопричина падения Xray целиком: при этом протоколе панель пишет в inbound `certificateFile`=`/opt/vpnpanel/certs/live/veil-…/fullchain.pem`, а `/opt/vpnpanel/certs` лежит `root:root drw-------` и не читается процессом Xray, который здесь под `User=nobody` => `permission denied` => xray не стартует => падала ВСЯ VPN. ## Что ставится

| Компонент | Что делает |
|---|---|
| Xray | VLESS + Reality VPN, Hysteria2, WireGuard — активируется кнопкой из панели |
| telemt | Telegram MTProto прокси с FakeTLS |
| veil-zapret2 | DPI-bypass для MTProto (nfqws2 + nft + lua) |
| vpnpanel | Веб-панель управления на порту 8443 |

## Что умеет панель

- VPN: включить/выключить Xray, ссылка и QR для v2rayNG, Streisand, Hiddify
- 19 протоколов по группам (Reality / VLESS / VMess / Trojan / Shadowsocks / Hysteria2 / WireGuard): VLESS + Reality и XHTTP + Reality, VLESS на WS/TCP/gRPC/XHTTP/SplitHTTP (с TLS), VMess и Trojan на WS/TCP/gRPC (с TLS), Shadowsocks AEAD, Hysteria2 (QUIC), WireGuard (UDP)
- TLS-протоколы получают автоматический самоподписной сертификат, XHTTP поддерживает HTTP/2 / HTTP/3 streaming — домен не нужен
- Протоколы не конфликтуют: каждый живёт на своём порту, старые ссылки не ломаются; новая ссылка всегда добавляется отдельным клиентом
- Telegram: MTProto-ссылка и QR, кнопка Отключить fix (zapret2)
- Несколько клиентов: добавлять, переименовывать, удалять
- Безопасность: смена логина и пароля панели
- Обновления: проверка новых версий из GitHub
- Статистика: аптайм сервисов Xray и telemt, количество клиентов, загрузка диска и памяти

## Стек

- Backend: Python 3 (стандартная библиотека)
- Frontend: один HTML-файл
- VPN-ядро: Xray-core (VLESS + Reality, xtls-rprx-vision)
- Прокси: telemt (MTProto + FakeTLS)
- DPI-fix: zapret2 + veil-mtproto.lua (nfqws2 + nftables)
- Управление: systemd

## Порты

install.sh сам находит свободные порты:

- Xray — панель ищет при первом включении VPN (443 → свободный)
- Telegram (telemt) — install.sh ищет при установке (7443 → свободный)
- Панель — install.sh ищет при установке (8443 → свободный)

Если 443 / 7443 / 8443 заняты — скрипт автоматически сдвинет на ближайший свободный и покажет актуальные порты в конце установки. Ничего настраивать вручную не надо.

## Опции install.sh

  --step N          только один шаг (0..6)
  --dry-run         показать команды, не выполнять
  --xray-port PORT  предпочитаемый порт Xray (по умолчанию 443)
  --tg-port PORT    предпочитаемый порт Telegram (по умолчанию 7443)
  --tls-domain NAME FakeTLS домен (по умолчанию my.aeza.ru)

## Логин и пароль панели

При первой установке install.sh генерирует случайный пароль.
Логин, пароль и порт сохраняются в /opt/vpnpanel/FIRST-LOGIN.txt и выводятся в конце установки.
Сменить — в панели, раздел Безопасность.
